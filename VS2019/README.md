# FluidSynth 2.6.3: native Visual Studio 2019 SF2/DLS DLL build

Open `FluidSynth.sln` in Visual Studio 2019 to build the library directly.
No CMake, project generation, dependency downloads or package manager is
required. This directory contains the native project, prepared configuration
headers and the complete GCEM dependency used by the build.

## Get this build

Select the `vs2019-sf2-only` branch in the Falcosoft/fluidsynth repository and
use **Code > Download ZIP**, or check out that branch in a local clone:

```console
git switch vs2019-sf2-only
```

This branch starts at upstream **v2.6.3**, commit
`cd8b576ae6d33b805378356e5b33ec9f9c5b2e1b`, the library version selected for the next
FluidSynth VSTi release. The `VS2019` directory contains the build
additions; upstream `src`, `include`, `LICENSE`, `AUTHORS` and other files remain
in their original locations.

The solution is `<repository>/VS2019/FluidSynth.sln`. The project obtains the
upstream source root from the parent of its own directory, so the clone can
have any directory name. A separate `Source` directory is not used.

These prepared headers, resource and source list are for **FluidSynth 2.6.3**.
When updating the upstream version, review them together before publishing new
DLLs. Tag the exact repository revision used for each binary release.

## Build in the IDE

1. Open `VS2019/FluidSynth.sln` in Visual Studio 2019 (16.11 recommended).
2. Select **Release** and **Win32** or **x64**.
3. Build the solution.

Install the normal Desktop development with C++ components, the v142 toolset
and a Windows 10 SDK. The project selects an installed Windows 10 SDK through
`WindowsTargetPlatformVersion=10.0`. If Visual Studio asks to retarget, retain
v142 and select an installed SDK.

Outputs, relative to the repository root:

| Platform | DLL |
| --- | --- |
| Win32 | `VS2019/bin/Win32/Release/libfluidsynth-3.dll` |
| x64 | `VS2019/bin/x64/Release/libfluidsynth-3.dll` |

A matching import library is produced beside each DLL. FluidSynth VSTi loads
the DLL dynamically and does not need the import library.

## Build from the command line

From a Developer Command Prompt for Visual Studio 2019, run:

```bat
VS2019\BUILD_ALL.cmd
```

The script locates the solution relative to itself and builds both platforms.
It can also be run from another working directory by supplying its full path.
Alternatively, from the repository root:

```bat
MSBuild VS2019\FluidSynth.sln /t:Build /p:Configuration=Release /p:Platform=Win32 /m
MSBuild VS2019\FluidSynth.sln /t:Build /p:Configuration=Release /p:Platform=x64 /m
```

## Use with FluidSynth VSTi

Copy the matching Win32 or x64 `libfluidsynth-3.dll` beside `FluidSynthVsti.dll`.
Keep the two architectures in separate plugin directories. Uncompressed SF2
SoundFonts and native DLS banks are supported; no `sndfile.dll` or separate
audio-decoder DLL is required.

## Build configuration

The settings extend the standalone VS 2019 SF2-only project with native DLS:

- Native v142 DLL project; Release Win32 and Release x64.
- Static Microsoft C/C++ runtime (`/MT`).
- `/O2`, `/Gy`, `/Gw`, `/GL`, `/LTCG`, `/OPT:REF` and `/OPT:ICF`.
- Explicit C compilation for `.c` files; C++17 for `.cpp` files, including
  the C++ voice mixer introduced upstream in 2.6.3.
- Precise floating point, with `/fp:fast` for the IIR implementation as in
  upstream's MSVC configuration.
- Win32 uses `/arch:IA32`; Windows target macros are set to Windows 7.
- Float DSP, C++11 OS abstraction and synthesis threads enabled.
- Native SF2 and DLS loading, SoundFont stacking, MIDI handling, reverb, chorus and
  in-memory rendering retained.
- libsndfile/SF3 decoding, external effects libraries, OpenMP,
  audio/MIDI device drivers, file output and networking disabled.
- No FluidSynth standalone command-line player is built.

`Config/config.h` contains the fixed MSVC feature configuration.
`Config/include` contains the prepared umbrella and version headers normally
generated by the upstream build. These include directories precede the upstream
headers. All 56 C/C++ compilation units are read directly from upstream `src`.

Visual Studio's local files and the `bin`/`obj` directories are ignored by the
local `.gitignore`.
